# mutation-verifier — 뮤테이션 검증

일부러 결함(변이)을 넣어 테스트가 감지하는지 확인한다. 회귀·아키텍처·코드 리뷰가 끝난 뒤
**단독으로** 실행한다(다른 검증과 동시에 돌리지 않는다).

## 작업 위치 — 반드시 임시 복제본

- `tool/cross_verify.sh` 로 실행됐다면 현재 디렉터리가 이미 복제본이다.
- 직접 실행한다면 먼저 복제본을 만들고 그 안에서만 작업한다:
  `bash tool/verify_copy.sh --stub-secrets "$(mktemp -d)/repo"` → 출력된 경로로 이동.
- 원본 작업 트리의 파일은 절대 바꾸지 않는다.

## 절차

1. 변경분(`git diff --cached`)에서 테스트가 지켜야 할 구현 코드를 고른다. 구현 변경 없이 테스트만
   추가됐다면 그 테스트가 다루는 함수를 대상으로 한다.
2. 변이를 3~10개 만든다: 조건 반전, 비교 연산자 경계(`<` ↔ `<=`), 반환값 교체, 예외 처리 제거,
   문자열·구분자 변경, 호출 삭제. 동작이 같아지는 변이(동등 변이)는 피하고, 생겼다면 따로 표시한다.
3. 변이마다 다음을 반복한다.
   1. 대상 파일을 백업한다(`cp <파일> <파일>.orig`).
   2. 변이 하나만 적용한다.
   3. 관련 테스트를 실행한다: `flutter test --no-pub <테스트 파일>`.
   4. 결과를 기록한다: killed(테스트 실패) / survived(테스트 통과) / 컴파일 오류.
   5. 백업으로 되돌리고(`cp <파일>.orig <파일>` 후 백업 삭제) 테스트가 다시 통과하는지 확인한다.
4. 마지막에 `git diff --cached` 와 `git diff` 로 변이가 남지 않았는지 확인한다.

## 판정 기준

- FAIL: 동등 변이가 아닌 survived 변이가 있다, 또는 변이 전 테스트가 이미 실패한다.
- PASS: 모든 변이가 killed 또는 동등 변이로 분류됐다.

## 출력 형식

```text
## 변이 결과
| # | 파일:줄 | 변이 | 결과 | 실행한 테스트 |

## survived 변이에 대한 테스트 보강 제안
- <변이 #> <추가할 테스트 사례>

## 복원 확인
- <명령> → <결과>

VERDICT: PASS | FAIL
```
